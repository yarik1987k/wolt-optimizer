# Wolt Offer Collector — Phase 0 (בדיקת היתכנות)

אפליקציית Android אישית, מקומית בלבד, שבודקת **האם בכלל אפשר** לתעד באופן פסיבי הצעות משלוח מאפליקציית השליחים של Wolt:
האם ההתראה מגיעה, מה יש בה, והאם פרטי ההצעה נגישים לקריאה מהמסך.

> **⚠ בטיחות:** אין להגדיר, לפתוח או לבדוק את האפליקציה בזמן נהיגה. בדיקות רק כשהרכב חונה.
> האפליקציה אינה שולחת התראות, צלילים או חלונות קופצים, ואינה דורשת ממך שום פעולה במהלך משמרת.

> **חשוב:** מקבלת התראה בלבד **אי אפשר לדעת אם ההצעה התקבלה או נדחתה**. הסרת התראה (`REMOVED`, גם עם `REASON_CLICK`) אינה קבלה ואינה דחייה. סטטוס ההצעה הוא `UNKNOWN` אלא אם תסמן/י אותו ידנית (Phase 1).

זהו פרויקט נפרד מ-Wolt Optimizer. הוא נמצא בתיקייה `WoltOfferCollector/` ואינו נוגע בקוד של ה-Optimizer.
מה נבדק בפועל ומה עדיין לא הוכח — ב-[FEASIBILITY_REPORT.md](FEASIBILITY_REPORT.md).

## מה האפליקציה עושה ומה לא

| עושה | לא עושה |
|---|---|
| מאזינה להתראות **רק** מהאפליקציה שבחרת ידנית (POSTED / UPDATED / REMOVED) | לא לוחצת, לא מקבלת/דוחה הזמנות, לא מבצעת מחוות (`performAction`/`dispatchGesture` לא קיימים בקוד) |
| בודקת לקריאה בלבד אם יש טקסט נגיש במסך של אותה אפליקציה | לא מציירת שכבות מעל Wolt, לא מקליטה מסך, לא עושה OCR, לא עושה polling |
| מסתירה **לפני שמירה**: שמות, כתובות, טלפונים וטקסט חופשי הופכים ל-`[TEXT]` / `[PHONE-REDACTED]` / `[#]` | לא שומרת טקסט גולמי בשום מקום (DB, לוגים, ייצוא) |
| שומרת רק ערכים לא-אישיים: סכום ₪, ק״מ, דקות, שעה, מספר עצירות/הזמנות, מילות ממשק מרשימה קבועה, view-id של רכיבים | אין הרשאת אינטרנט, אין שרת, אין חשבון, אין Firebase/אנליטיקה |
| **חריג יחיד:** שם מסעדת האיסוף מכרטיס הצעה — השורה הראשונה מתחת לשורת המרחק — נשמר כטקסט, רק אם אין בו טלפון, מספר ארוך או יותר מ-8 מילים | כתובת היעד / הלקוח **לא נשמרת בכלל** |
| ייצוא JSON רק ביוזמתך דרך חלון שמירה של המערכת | לא משנה את Wolt Optimizer |

## דרישות

- מכשיר: **Android 8.0 (API 26) ומעלה**. נבדק על אמולטור Android 14 (API 34).
- לבנייה: macOS/Linux, JDK 17+, Android SDK עם platform 35 ו-build-tools. (על המחשב הזה כבר מותקנים: Homebrew `openjdk@17` ו-SDK ב-`/opt/homebrew/share/android-commandlinetools`.)

## בנייה

```bash
cd WoltOfferCollector
```

```bash
./scripts/build-apk.sh
```

הסקריפט מריץ את בדיקות היחידה, בונה APK במצב debug ומעתיק אותו ל-`dist/WoltOfferCollector-0.1.0-phase0-debug.apk`.
אפשר גם לפתוח את התיקייה ב-Android Studio.

בדיקות במכשיר/אמולטור מחובר (Room DAO + אימות סכמה):

```bash
./gradlew :app:connectedDebugAndroidTest
```

## התקנה על הטלפון

1. בטלפון: הגדרות ← אודות הטלפון ← הקש/י 7 פעמים על "Build number" ← חזור/י ← אפשרויות מפתח ← הפעל/י **USB debugging**.
2. חבר/י בכבל ואשר/י את טביעת המחשב בטלפון.
3. התקנה:

```bash
/opt/homebrew/share/android-commandlinetools/platform-tools/adb install -r dist/WoltOfferCollector-0.1.0-phase0-debug.apk
```

(אפשר גם להעביר את קובץ ה-APK לטלפון ולפתוח אותו — יש לאשר "התקנה ממקורות לא ידועים".)

## הפעלה (כשהרכב חונה)

1. פתח/י **Offer Collector** ← קרא/י את מסך ההסכמה ← סמן/י הסכמה להתראות, ואם רוצים — הסכמה נפרדת לקריאת מסך ← "אישור והמשך".
2. **בחירת אפליקציה מותקנת** ← בחר/י ידנית את אפליקציית השליחים של Wolt. האפליקציה לא מנחשת; "נראה כמו Wolt" הוא רמז בלבד.
3. **פתיחת הגדרות גישה להתראות** ← הפעל/י את "Offer Collector".
4. (אופציונלי) **פתיחת הגדרות נגישות** ← Offer Collector — read-only screen check ← הפעלה.
5. **Android 13 ומעלה, APK שהותקן ידנית:** אם המתג אפור או מופיעה הודעה "Restricted setting" — לחץ/י **פרטי אפליקציה (Restricted settings)** ← תפריט ⋮ למעלה ← **Allow restricted settings** ← אשר/י, ואז חזור/י לשלב 3/4.
6. **Start Monitoring**. במסך הסטטוס צריך לראות ✓ ב"שירות ההתראות מחובר", ואם הופעל — גם ב"שירות נגישות מחובר".
7. עבוד/י כרגיל. אין צורך לפתוח את האפליקציה במשמרת.
8. אחרי המשמרת, כשחונים: **Diagnostics** לצפייה, **Export Diagnostics JSON** לשמירת קובץ.

### בדיקת היתכנות מומלצת (Phase 0)

כשחונים ומגיעה הצעה אמיתית: פתח/י את ההצעה ב-Wolt כרגיל. אחר כך פתח/י Diagnostics ובדוק/י:
- האם יש אירוע `POSTED` של התראה? האם `title_redacted` / `text_redacted` ריקים (`NULL`)?
- האם יש צילום מצב עם `VISIBLE`? או `NO_ACCESSIBLE_TEXT` עם סיבה (`ROOT_NULL` / `NO_TEXT_NODES`)?
- אילו שדות הופיעו: `amounts`, `dist`, `stops`? ומה ה-`latency_ms`?

ייצא/י JSON ושלח/י אותו (או את סיכום ה-`summary`) כדי לעדכן את דוח ההיתכנות.

## הפסקה, ביטול ומחיקה

- **Stop Monitoring** — עוצר מיד: שירות ההתראות משתחרר מהמערכת (`requestUnbind`), ושירות הנגישות מפסיק לקבל אירועים (מסנן אירועים ריק). נבדק באמולטור.
- **ביטול הרשאות** — הגדרות ← גישה להתראות / נגישות ← כיבוי. נבדק באמולטור: האיסוף נעצר מיד.
- **הגדרות ומחיקה ← Delete All Data** — מוחק את כל האירועים ומחליף את ה-salt של המזהים המגובבים.
- **ביטול הסכמה** — מפסיק ניטור ומחזיר למסך ההסכמה.
- הסרת האפליקציה מוחקת את כל המידע. גיבוי ענן חסום (`allowBackup=false`).

## הערות ריצה ברקע

- השירותים מופעלים על ידי המערכת ופועלים גם כשהאפליקציה סגורה. נבדק באמולטור: האיסוף עבד אחרי התקנה מחדש בלי לפתוח את ה-UI כלל.
- יצרנים מסוימים (Samsung, Xiaomi, OnePlus ועוד) עלולים לעצור שירותים ברקע. אם אירועים מפסיקים להגיע: הגדרות ← סוללה ← החרגת Offer Collector מאופטימיזציה. **לא נבדק על מכשיר אמיתי.**
- כלי אוטומציה/נגישות אחרים (למשל `uiautomator`) עלולים להשהות זמנית את שירות הנגישות. נצפה באמולטור.

## מדיניות ותנאים

הקוד מיועד לשימוש אישי על מכשיר שלך. הוא **לא** מיועד להפצה ב-Google Play במתכונתו הנוכחית: מדיניות ה-Accessibility API של Play מגבילה שימושים שאינם נגישות.
לפני שימוש עם אפליקציית Wolt Partner — באחריותך לוודא שהשימוש תואם את תנאי השימוש שלה. היתכנות טכנית אינה אישור לשימוש.

## מה הלאה

Phase 1 (נרמול ל-`offer_candidate`, סימון ידני של ACCEPTED/DECLINED/EXPIRED, ייצוא CSV) **לא מומש בכוונה** — לפי האפיון, רק אחרי ששער ההיתכנות עבר על מכשיר אמיתי עם הצעת Wolt אמיתית.
