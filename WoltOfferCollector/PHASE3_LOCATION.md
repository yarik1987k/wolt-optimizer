# Phase 3 — איסוף מיקום וצפיפות הצעות (Collector 0.4.0)

**APK:** `dist/WoltOfferCollector-0.4.0-phase3-location-debug.apk`. מותקן על Galaxy A55 (Android 16) מתאריך 29.10.2026.
- Wolt Optimizer **לא שונה**. בדקתי שהוא קורא את פורמט הייצוא החדש כמו שהוא.
- אין מנוע חיזוי ואין המלצות.

## מה נוסף מעל 0.3.0
| נושא (סעיף במפרט) | מה נבנה |
|---|---|
| §4 מצבי איסוף | איסוף רק בין "התחלת משמרת" ל"סיום משמרת", ורק עם הסכמה. בסיום: קודם עוצרים את עדכוני ה-GPS, אחר כך את השירות, ומקטע המעקב נסגר. בזמן איסוף מוצגת התראה קבועה (נוספה הרשאת `POST_NOTIFICATIONS`). המצב מוצג בכרטיס הבית ובאבחון |
| §5 דגימה באירועים | `OFFER_PRESENTED`, `AVAILABLE_SCREEN` (= AVAILABLE), `OFFLINE`, `DELIVERY_SCREEN`, ובנוסף `DELIVERY_ACCEPTED`, `PICKUP_DONE`, `DROPOFF_DONE`, `DELIVERY_COMPLETED` מגלאי המשלוחים. הגלאי רץ על אירועי המשמרת כל 3 שניות לכל היותר |
| §5 מיקום בזמן האירוע | נבחר ה-fix הקרוב ביותר **לזמן האירוע** מתוך מאגר של 5 דקות בזיכרון. אם אין fix בטווח של 60 שניות מהאירוע: `STALE_FIX` או `NO_FIX`, ולא מיקום ישן. נשמר `location_age_ms` = ההפרש בין זמן האירוע לזמן ה-fix |
| §5 ראיה | `state_evidence` מועתק מהגלאי או מהמסווג (OBSERVED, ESTIMATED או UNKNOWN). הדגימה עצמה לא מעלה את רמת הראיה |
| §6 דגימה תקופתית | זרם רציף (`requestLocationUpdates`, `HIGH_ACCURACY`) כל 30, 45 או 60 שניות (ברירת מחדל 45, בהגדרות). כשהמכשיר עומד (3 fixes ברדיוס 50 מ׳ ובמהירות מתחת ל-1 מ׳/ש׳) המרווח מתארך ל-120 שניות, ואפשר לכבות את זה |
| §6 בלי fix | אחרי 2 מרווחים בלי fix נשמרת דגימה `PERIODIC / NO_FIX`. **אף פעם לא משכפלים את המיקום הקודם** |
| §6 זמן זמין | דגימות תקופתיות מקבלות טריגר חדש `PERIODIC`, ולא `WAIT_PERIODIC`, ולכן ה-Optimizer הנוכחי **לא סופר אותן כזמן זמין**. המצב באותו רגע נשמר ב-`state_candidate` ו-`state_evidence` |
| §6 פערים | פער = שקט ארוך מ-2.5 × המרווח הארוך הצפוי, או שירות שנהרג (SERVICE_STOPPED). הפערים מוצגים באבחון ונכללים בייצוא |
| §6 סוללה | אחוז הסוללה בתחילת המשמרת, בסופה ובכל דגימה, וסימון אם המכשיר נטען. החישוב: ירידה ב-% לשעה, רק במשמרות של 30 דקות ומעלה בלי טעינה. **זו סוללת כל המכשיר**, לא הצריכה של האפליקציה לבד |
| §7 מודל | `location_samples` (v4: source, state_evidence, speed_mps, location_age_ms, event_at_utc, event_key, battery_pct, debug_lat/lon). `shift_sessions` = LocationSession, והספירות מחושבות. **OfferLocation לא נשמר בטבלה** — הוא מחושב מהצעות ודגימות, כדי לא לשכפל נתונים (§7, "אין לשכפל") |
| §8 פרטיות | רשת g500 של כ-500×500 מ׳ במקום H3 (שקולה לה, בלי ספרייה נייטיבית). כברירת מחדל נשמר רק מזהה התא. **מצב Debug** (הגדרות): קואורדינטות מדויקות נשמרות במכשיר בלבד, נמחקות אוטומטית אחרי 24 שעות, נמחקות מיד כשמכבים את המצב או בכפתור, ו**אף פעם לא נכללות בייצוא** (יש בדיקה לזה) |
| §9 ייצוא | נוספו `schema_version: 4`, `location_parser_version: "loc-2"`, `location_sessions`, `offer_locations`, `location_quality_summary`. ב-`location_samples` נוספו שדות. `shift_sessions` וכל השדות הקיימים נשארו עם אותה משמעות |
| §10 אבחון | כרטיס "מיקום ואזורים": הרשאה (מדויק, משוער או אין), התראה, שירות פועל ובאיזה מרווח, דגימות לפי סטטוס, הצעות עם וללא מיקום, דיוק חציוני, גיל המיקום החציוני בהצעה, תאים, פערים, סוללה, ומפת תאים פשוטה (כהה = יותר דגימות, נקודה = הצעה) |

**שמות השדות במפרט מול הייצוא:**
| במפרט | בייצוא |
|---|---|
| `sessionId` | `shift_id` |
| `timestampUtc` | `observed_at_utc` (זמן הדגימה), `event_at_utc` (זמן האירוע) |
| `gridCellId` | `cell_id` |
| `accuracyMeters` | `accuracy_m` |
| `locationAgeMs` | `location_age_ms` |
| `captureStatus` | `capture_status` |
| `latitude`/`longitude` | לא מיוצאים. קיימים רק במצב Debug, על המכשיר |

**`match_confidence` ב-`offer_locations`:**
- **HIGH:** דגימה שנלקחה בגלל ההצעה, עם fix של עד 30 שניות.
- **MEDIUM:** אותו דבר, עם fix של 30–60 שניות.
- **LOW:** רק דגימה אחרת תקינה, בטווח של עד 60 שניות מההצעה.
- **NONE:** אין מיקום תקין.

## בדיקת שטח
### שלב 1 — כשהטלפון נייח (כ-10 דקות, בבית)
1. Offer Collector ← בית ← "משמרת ואזורים" ← מסמנים הסכמה ← **"התחלת משמרת"**.
2. מאשרים: **מיקום מדויק** ← **"בזמן השימוש באפליקציה"** ← **התראות: אפשר**.
3. בודקים שמופיעה התראה "איסוף מיקום פעיל" ושמופיע סמל המיקום בשורת המצב.
4. מכבים את המסך ל-10 דקות.
5. **"סיום משמרת"**. בודקים שההתראה נעלמה.
6. בטאב אבחון, בכרטיס "מיקום ואזורים", אמורים לראות:
   - בערך 5–15 דגימות (המרווח מתארך ל-120 שניות כשהטלפון עומד);
   - אזור אחד;
   - 0 פערים.

### שלב 2 — משמרת אמיתית (איסוף פסיבי בלבד)
1. **כשחונים:** "התחלת משמרת". **אחר כך לא נוגעים ב-Offer Collector.**
2. עובדים כרגיל, כולל Waze או אפליקציית ניווט אחרת.
3. **כשחונים, בסוף:** "סיום משמרת" ← ייצוא JSON, או לחבר בכבל.
4. כדאי לרשום מה היה אחוז הסוללה בהתחלה ובסוף, ואם הטלפון נטען.

### הדוח שאכין אחרי המשמרת
- מספר ההצעות שנאספו.
- אחוז ההצעות עם מיקום תקין, ופילוח לפי `match_confidence`.
- מספר התאים שבהם נצפו הצעות.
- זמן השהייה שנמדד בכל תא, מחולק לזמין, במשלוח ולא ידוע (לפי `state_candidate`).
- פערי ניטור.
- איכות המיקום: דיוק חציוני, גיל המיקום בהצעה, ופילוח לפי סטטוס.
- צריכת סוללה.

⚠ גם אחרי הדוח: אזור עם יותר הצעות **אינו בהכרח** האזור המשתלם ביותר.
