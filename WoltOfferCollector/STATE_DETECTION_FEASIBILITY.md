## הצעה לשמירה וחיבור ל-Optimizer (רק אם הבדיקות יצליחו)

**ב-Collector — טבלת `courier_state_events`:**

| שדה | תוכן |
|---|---|
| `observed_at_utc` | זמן |
| `state` | `OFFER_PRESENTED` / `DELIVERY_ACTIVE` / `AVAILABLE` / `OFFLINE` / `UNKNOWN` |
| `evidence` | `OBSERVED` — סמן ישיר שאומת בבדיקות / `ESTIMATED` — אות עקיף (למשל התראה קבועה בלבד) / `UNKNOWN` — פער: Wolt ברקע בלי אות, שירות מנותק, אפליקציה נסגרה |
| `signal` | שם הסמן, למשל `notif:incoming_task`, `screen:StatusButtons.SwipeButton#shape` |
| `parse_version` | גרסת הפרסר |

**כללים:**
- לא מסיקים **קבלה** מהיעלמות כרטיס. קבלה = רק DELIVERY_ACTIVE שנצפה בוודאות זמן קצר אחרי ההצעה, או סימון ידני.
- לא מסיקים **סיום משלוח** מהיעלמות מסך. סיום = רק סמן סיום שנצפה, או מעבר ל-AVAILABLE שנצפה. אחרת — `UNKNOWN`.
- כל פער באותות הופך למרווח `UNKNOWN` — לא "ממלאים" אותו.

**הייצוא:** שדה חדש `state_events` בקובץ ה-JSON הקיים, בגרסת פורמט חדשה (`diagnostics-v2`).

**ב-Optimizer:**
- מודל `CourierStateInterval` (מצב, התחלה, סוף, `evidence`, מזהי האירועים) שנבנה בייבוא — באותו מנגנון כפילויות של ההצעות.
- **משך משלוח** = מרווח DELIVERY_ACTIVE שגם תחילתו וגם סופו `OBSERVED`. **זמן המתנה** = AVAILABLE → ההצעה הבאה.
- ממוצעים ותצוגות רק ממרווחים ודאיים. מרווחים משוערים מוצגים בנפרד.
- **קישורים:** הצעה ← מרווח DELIVERY_ACTIVE שאחריה (כראיה לקבלה, לצד הסימון הידני) ← משמרת ← תשלום בדוח.
- **בסימולטור:** "זמן ממוצע למשלוח" ימולא אוטומטית רק כשיש מספיק מרווחים ודאיים, עם n ותווית ביטחון. עד אז — "לא ידוע".

## עדכון — DELIVERY_ACCEPTED / DELIVERY_COMPLETED (גרסה `0.2.2`, detector `delivery-detect-1`)

**עובדה מהשליח (29.10.2026):** קבלת משלוח וסיומו מתבצעים **בתוך אפליקציית Wolt** — קבלה בלחיצה, סיום בהחלקה. לכן ברגעים האלה Wolt בחזית ושירות הנגישות יכול לקרוא את המסך. זה מה שהופך את שתי נקודות המדידה לישימות.

### כלל האירוע: פעולה + מסך מאשר
| אירוע | פעולה נצפית | מסך מאשר (תוך 20 שניות) | אחרת |
|---|---|---|---|
| **DELIVERY_ACCEPTED** | לחיצה על "принять" (`TYPE_VIEW_CLICKED`) | מסך משלוח: מילות שלב או סליידר שלב, לא כרטיס הצעה | `ACTION_UNCONFIRMED` / UNKNOWN |
| **PICKUP_DONE** | החלקה או לחיצה עם "забрал" / picked / נאסף | מסך שלב משלוח | UNKNOWN |
| **DROPOFF_DONE** | החלקה או לחיצה עם "доставлено" / delivered / נמסר / завершить | מסך עצירה הבאה (עם סליידר שלב) **או** מסך שאחרי משלוח | UNKNOWN |
| **DELIVERY_COMPLETED** | כמו מסירה | מסך הבית, מסך סיכום (מילים כמו доход / earnings / רווח, ללא סליידר שלב), או כרטיס הצעה חדש | UNKNOWN |

- **אין אירוע בלי פעולה נצפית.** סדרת מסכים בלי לחיצה או החלקה לא יוצרת שום אירוע — גם אם הם נראים כמו משלוח.
- **"Trip":** מתחיל בקבלה מאושרת. קבלה נוספת בזמן נסיעה = הזמנה נוספת באותו Trip (משלוח מקובץ). כל מסירה = אירוע נפרד. ה-Trip נגמר רק כשאחרי מסירה מופיע מסך שאינו שלב משלוח.
- **משך משלוח** = סיום פחות התחלה — רק כששניהם OBSERVED. **זמן המתנה** = מסיום נצפה עד הקבלה הנצפית הבאה. פער בניטור (ניתוק או עצירה) הופך סיום פתוח ל-UNKNOWN ושובר את שרשרת ההמתנה.
- **`rule_validated=false`:** חתימות "מסך משלוח" ו"מסך שאחרי משלוח" עדיין **השערה**. מעולם לא נצפה משלוח אמיתי בזמן ניטור. הן יאומתו או יתוקנו אחרי בדיקה B.

### מה הוכח ומה לא
| | סטטוס |
|---|---|
| לכידת לחיצת "принять" | ✅ הוכח באמולטור, דרך הצינור האמיתי של Android |
| לכידת החלקת סיום | ⏳ לא הוכח. נבנו 3 ערוצים: כל אירוע מרכיב החלקה, מיקום הסליידר (`RangeInfo`), ותווית הסליידר. באמולטור Chrome לא שלח שום אות על החלקה |
| מסך מאשר אחרי קבלה ואחרי סיום | ⏳ לא נצפה. החתימות הן השערה |
| חותמות זמן אמינות להתחלה ולסיום | ⏳ **תלוי בבדיקה B** |

### בדיקות
8 בדיקות יחידה לזיהוי: משלוח מלא, קבלה בלי מסך מאשר, היעלמות בלי פעולה, החלקה בלי מסך מאשר, משלוח מקובץ (2 הזמנות, 2 איסופים, 2 מסירות → Trip אחד), זמן המתנה, פער ניטור ודחייה. סה״כ 63 בדיקות יחידה עוברות.

### מסירה אחת מול סוף ה-Trip (משלוח מקובץ)
- **אחרי מסירה מופיע מסך שלב עם סליידר** → `DROPOFF_DONE` (`screen.next_stop`), ה-Trip ממשיך.
- **אחרי מסירה מופיע מסך הבית, סיכום או הצעה חדשה** → `DROPOFF_DONE` + `DELIVERY_COMPLETED`.
- **מספר מסירות צפוי:** אם בכרטיס ההצעה מוצג מספר משלוחים (למשל "3 доставки"), ל-Trip יש `expected_dropoffs`.
  - מסך סיכום **לפני** המסירה האחרונה = מסירת ביניים — ה-Trip ממשיך.
  - מסך הבית או הצעה חדשה **לפני** המסירה האחרונה = סתירה (`TRIP_END_CONFLICT`) — הסיום UNKNOWN, ללא משך.
- **משך ה-Trip** = מהקבלה **הראשונה** עד המסירה **האחרונה** המאושרת.
- **כרטיס הצעה משויך לקבלה אחת בלבד** — תוקן באג שבו מחיר של כרטיס קודם "נדבק" לקבלה מאוחרת יותר.
- **מגבלה:** כשהכרטיס **לא** מציג מספר משלוחים ו-Wolt מציג מסך סיכום קצר בין מסירות (בלי סליידר), ה-Trip ייסגר מוקדם מדי. בבדיקה B יתברר אם זה קורה בפועל.
- 4 בדיקות יחידה לתרחישים האלה, כולל 3 הזמנות → סיום רק במסירה השלישית. סה״כ 67 בדיקות יחידה.
